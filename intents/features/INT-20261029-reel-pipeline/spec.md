## 1. Summary

`pixelreel` is a Rust command-line tool in `cli/`. It turns a Markdown
storyboard, talking-head recordings, ElevenLabs lines, pixellab scenes and
outside animations into one rendered video, scored with `cozy-score`. The
storyboard is the source of truth. Every timing decision is stored as text
in the project folder, and raw media is never modified.

## 2. Decisions

These were settled in the design discussion and are fixed for this spec.

| Topic | Decision | Why |
|---|---|---|
| Command name | `pixelreel` | Chosen by the owner |
| Location and language | Rust crate in `cli/` | Matches `cozy-score` |
| Music | Calls the `cozy-score` library in-process, as a path dependency on `../tooling/cozy-score` | Shares the plan types and renderer; avoids running a subprocess and parsing its JSON |
| Storyboard format | Markdown, with a one-line heading per beat | Reads like a script and is quick to write |
| Composition | A frame compositor written in this crate, for `scene:` beats only. Everything else (cuts, overlays, concatenation, encoding) uses `ffmpeg` | Sprite animations triggered by spoken words need frame-level control; `ffmpeg` already does the rest well |
| Transcription | Local `whisper.cpp` (`whisper-cli` on `PATH`) | Free and works offline |
| Speech synthesis | ElevenLabs text-to-speech with timestamps | Already part of the workflow; gives word timing directly |

## 3. Concepts

- **Beat:** one storyboard unit. It has an id, a `cozy-score` video type, a
  picture and zero or more lines.
- **Picture:** what is on screen during a beat. It is one of:
  - `face`: the talking-head recording
  - `scene:<id>`: a pixellab scene
  - `asset:<id>`: an outside animation
  - `card`: a placeholder showing the beat's script, used only while
    storyboarding; `render --final` rejects it
- **Line:** one spoken sentence or phrase. It is either a **you-line**,
  recorded by J. Law, or a **VO line**, generated by ElevenLabs. Lines have
  ids `<beat>.<n>`, numbered from 1 within the beat. The voice and the
  picture are independent: a you-line can play over a scene (an L-cut).
- **Cue:** a `{#name}` marker after a word in a line. Scenes and camera
  moves can start on it.
- **Chapter:** a beat that starts a YouTube chapter.
- **Lock:** `pixelreel cut lock` freezes exact times into
  `build/timeline.json`. Before the lock, all times are estimates. After
  it, scenes, assets and music fit exact times.

## 4. Crate and dependencies

- The crate lives in `cli/` and builds a binary named `pixelreel`.
- It is a standalone crate with an empty `[workspace]` table, like
  `cozy-score`.
- It pins the same toolchain as `cozy-score` (`rust-toolchain.toml`,
  currently `1.97.0`) and pins dependencies to exact versions, with
  `Cargo.lock` committed.
- It depends on `cozy-score = { path = "../tooling/cozy-score" }`.
- External programs, each checked at the start of the commands that need
  them:

| Program | Needed by | When it is missing |
|---|---|---|
| `ffmpeg` and `ffprobe` | `take add`, `asset add`, `animatic`, `scene preview`, `render` | Error, naming the command |
| `whisper-cli` (whisper.cpp) | `take add` | Error, naming the command |

- ElevenLabs needs the `ELEVENLABS_API_KEY` environment variable. The key
  is never written to disk or logs.
- `PIXELREEL_ELEVENLABS_URL` overrides the API base URL, for tests.
- CI: `.github/workflows/pixelreel.yml` copies the `cozy-score` workflow.
  It runs `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`
  and `cargo test --locked --release` on PRs that touch `cli/**` or
  `tooling/cozy-score/**`, with `ffmpeg` installed on the runner.

## 5. Project layout

```
<project>/
  pixelreel.yaml     # settings: size, fps, pixel scale, feel, voices, mix
  storyboard.md      # script + beats: the source of truth
  cuts.yaml          # timing edits, written by `pixelreel cut`
  picks.yaml         # chosen VO takes and music seed
  takes/             # raw camera recordings, never modified
  vo/                # ElevenLabs audio + word timings, cached by hash
  scenes/<id>/       # pixellab export, layout.png, scene.yaml
  assets/assets.yaml # registered outside animations (files may live elsewhere)
  build/             # derived: timeline, animatic, score, renders, cache
```

Everything under `build/` can be deleted and rebuilt. Everything outside
`build/` is either user input or a recorded decision.

## 6. File formats

### 6.1 `pixelreel.yaml`

```yaml
size: 1920x1080          # output size; must be an integer multiple of the scene canvas
fps: 30
pixel_scale: 6           # 320x180 pixellab canvas x 6 = 1920x1080
feel: spring             # passed to cozy-score: spring | summer
voices:
  sprout:
    voice_id: "<elevenlabs-voice-id>"
    model: eleven_multilingual_v2
    stability: 0.5
    similarity: 0.75
speech:
  wpm: 155               # estimate for unrecorded you-lines; recalibrated from takes
  pause: 0.25            # estimated pause between lines, seconds
transcribe:
  model: ~/models/ggml-base.en.bin
cut:
  pre_roll: 0.08         # kept before a line's first word
  keep_breath: 0.12      # kept after a line's last word
  max_gap: 0.30          # longest natural pause kept between back-to-back lines
mix:
  duck_db: -9
  duck_attack_ms: 60
  duck_release_ms: 350
  target_lufs: -14
  true_peak_dbtp: -1
```

Every key except `voices` has the default shown. `init` writes the file
with all defaults filled in.

### 6.2 `storyboard.md`

```markdown
---
title: I Built a Farm That Runs Itself (30-Day Devlog)
---

## hook | cold-open-hook | face
chapter: Can a farm run itself?
Thirty days ago this field was empty.
Today it plants, waters and harvests itself.

## hook-tease | cold-open-hook | scene:farm-night
And I haven't touched it in a week{#lights-on}.

## title | title-sting | asset:logo-intro
length: 4s
```

**Front matter.** Optional YAML. Only `title` is read.

**Beat heading.** `## <id> | <type> | <picture>`
- `id` matches `[a-z0-9][a-z0-9-]*` and is unique in the storyboard.
- `type` is a `cozy-score` video type id.
- `picture` is `face`, `card`, `scene:<id>` or `asset:<id>`.

**Directives.** `key: value` lines placed right after the heading, before
the first script line:

| Directive | Meaning |
|---|---|
| `chapter: <title>` | This beat starts a YouTube chapter |
| `length: <time>` | The beat's length, as `4s`, `23.5s` or `0:23`. In a beat with no lines, it is required unless the picture is an asset, which then uses its own duration. In a beat with lines, it is a minimum: the picture continues after the last line |
| `under: <picture>` | The picture shown beneath an `asset:` that has alpha. Accepts `face` or `scene:<id>` |

**Lines.** Each other non-empty line is a script line.
- `VO(<voice>): <text>` is a VO line. `<voice>` must be a key of
  `voices` in `pixelreel.yaml`.
- Any other line is a you-line.
- `{#name}` immediately after a word marks a cue. Cue names are unique in
  the storyboard. Cue markers are stripped before speech synthesis and
  captions.
- A line that is only `…`, and HTML comments, are notes. They are ignored.

**Validation.** `pixelreel` reports every error in one pass, as
`cozy-score` does. These are errors:
- an unknown video type, picture form, voice or directive;
- a duplicate beat id or cue name;
- a voiceless beat with no `length:` whose picture is not an asset;
- `under:` on a beat whose picture is not an asset;
- a storyboard with no beats.

### 6.3 `cuts.yaml`

`pixelreel cut` writes this file. It stays readable and editable by hand.

```yaml
lines:
  hook.2:   { out: -0.20 }            # seconds added to the aligned out point
  intro.1:  { take: A003 }            # use this take's read instead of the default
beats:
  hook-tease: { lead: 0.4, length: +0.21 }
tighten: { max_gap: 0.30, keep_breath: 0.12 }
```

### 6.4 `picks.yaml`

```yaml
vo:
  quote.1: 2         # take number from `vo gen --takes`
score:
  seed: 7
```

### 6.5 `build/timeline.json` (written by `cut lock`)

```jsonc
{
  "pixelreel": "0.1.0",
  "inputs": "sha256:…",            // hash of storyboard, cuts, picks, takes, vo
  "fps": 30,
  "duration": 460.0,
  "beats": [
    {
      "id": "hook", "type": "cold-open-hook", "picture": "face",
      "start": 0.0, "end": 8.04, "chapter": "Can a farm run itself?",
      "lines": [
        {
          "id": "hook.1", "voice": "you",
          "source": {"take": "A002", "in": 3.12, "out": 6.40},
          "start": 0.0, "end": 3.28,
          "words": [{"w": "Thirty", "start": 0.08, "end": 0.41}]
        }
      ],
      "cues": {}
    }
  ]
}
```

Times are in seconds from the start of the video, rounded to the frame
grid (`1/fps`). The same inputs give a byte-identical file.

### 6.6 `scenes/<id>/scene.yaml` (provisional)

This format is provisional until the open question about pixellab exports
(§13) is answered. The parts that are expected to stay are the canvas,
named layers, named sprite animations, cue triggers and camera keyframes.

```yaml
canvas: 320x180
fps: 12                       # sprite animation rate
duration: 6s                  # natural length; defaults to the longest one-shot animation
layers:
  - id: sky
    image: sky.png
  - id: sprinkler
    sheet: sprinkler.png
    frame: 32x32
    at: [140, 120]
    anims:
      idle:  { frames: 0-3, loop: true }
      spray: { frames: 4-15 }
    play: idle
camera:
  - { at: 0s,  pos: [0, 0] }
  - { at: end, pos: [40, 0], ease: in-out }   # `at` also accepts "#cue"
cues:
  sprinkler: { layer: sprinkler, play: spray }
```

### 6.7 `assets/assets.yaml`

```yaml
logo-intro: { path: ~/channel/logo-intro.mov, sha256: "…", fit: trim,      alpha: false, audio: keep }
quote-card: { path: assets/quote-card.mov,    sha256: "…", fit: hold-last, alpha: true,  audio: keep }
```

## 7. Commands

### 7.1 Conventions

- Results go to stdout; `--json` gives machine-readable output where
  noted.
- Warnings go to stderr as `warning: …` and errors as `error: …`, one per
  line. All errors found are reported before exiting.
- Exit codes: `0` on success, `1` on any error, and for
  `check --youtube` when a check fails.
- Every command takes `-C <dir>` (the project directory; default `.`).
- Every command can be re-run. Only outputs whose input hash changed are
  rebuilt (§10).

### 7.2 `pixelreel init <dir>`

| Option | Default |
|---|---|
| `--size WxH` | `1920x1080` |
| `--fps N` | `30` |
| `--pixel-scale N` | `6` |
| `--feel spring\|summer` | `spring` |

Creates `<dir>` with `pixelreel.yaml`, a commented `storyboard.md`
template, an empty `cuts.yaml` and `picks.yaml`, and the folders from §5.
It refuses to write into a directory that is not empty.

### 7.3 `pixelreel board [--json]`

Parses and validates the storyboard, then prints one row per beat:

```
 #  beat         type              picture           voice        est    at
 1  hook         cold-open-hook    face              you ×2       0:08   0:00
```

The footer gives the estimated total, the number of you-lines and VO
lines, and how many VO lines are not generated yet.

Estimates are computed as follows:
- **You-lines:** words ÷ `speech.wpm`. Once takes exist, the rate is
  recalibrated from J. Law's measured median.
- **VO lines:** the picked take's real length; words ÷ `wpm` if not
  generated yet.
- **Pauses:** `speech.pause` between lines.
- **Beats without lines:** `length:`, or the asset's duration.

When the timeline is locked, the table shows locked times instead, marked
`locked`.

### 7.4 `pixelreel animatic [--tts]`

Writes `build/animatic.mp4` at 960×540 using estimated or locked times.
- Each beat shows `scenes/<id>/layout.png` if it exists. Otherwise it shows
  a card with the beat id, type and script.
- Silent by default. With `--tts`, all lines (you-lines included) are
  voiced with the first voice in `pixelreel.yaml`, cached as in §7.5.
- If a score has been rendered, its music plays under the animatic.

### 7.5 `pixelreel vo gen [beat…] [--voice <id>] [--takes N] [--force]`

Generates every VO line in the named beats, or in all beats if none are
named.
- Calls ElevenLabs text-to-speech with timestamps for the line's voice,
  with cue markers stripped.
- `--takes N` (default 1) makes N requests with seeds 1…N.
- `--voice` limits generation to lines that use that voice.
- **Outputs:** `vo/<hash>-<n>.wav` (44.1 kHz) and
  `vo/<hash>-<n>.words.json` (word start and end times, built from the
  character alignment).
- **Hash:** covers the text, voice id, model, voice settings and seed.
  Files that already exist are never requested again unless `--force` is
  given.
- If a line belongs to a locked timeline, `vo gen` warns that the
  timeline must be re-locked.

### 7.6 `pixelreel vo pick <beat>[.<line>] <n>`

Records take `n` in `picks.yaml` for the line, or for every VO line in the
beat. Without a pick, take 1 is used.

### 7.7 `pixelreel take add <file…>`

1. Probes each file with `ffprobe` and extracts 16 kHz mono audio with
   `ffmpeg`.
2. Transcribes it with `whisper-cli` and word timestamps. The transcript
   is cached in `build/takes/<name>.transcript.json`, keyed by the file's
   hash.
3. Aligns transcript words to you-lines with a word-level sequence
   alignment. Matching ignores case and punctuation; numbers match in
   either digit or spelled-out form.
4. Finds each read of each line. A read is **complete** when it matches
   at least 85% of the line's words, including its first and last word.
5. Uses the last complete read by default, ordering files by the order
   they were added and reads by time within a file.
6. Writes `build/takes/<name>.align.json` and prints a report:
   - the lines covered, with their read count;
   - lines with no complete read;
   - unmatched transcript stretches longer than 2 s (ad-libs).

The take name is the file stem (`A001`). Files are referenced by path and
never copied or modified.

### 7.8 `pixelreel cut …`

Edits are written to `cuts.yaml`. While the timeline is locked, every
`cut` subcommand except `show` and `unlock` refuses to run.

| Subcommand | Effect |
|---|---|
| `show [beat] [--json]` | Each line's take, source in and out points, video times and the gaps between lines |
| `tighten [--max-gap s] [--keep-breath s]` | Sets the join rules from §8.2 |
| `set <beat>.<line> [--in ±s] [--out ±s]` | Adds an offset to the aligned in or out point |
| `set <beat> --length ±s` | Pads or trims the end of the beat. The picture is held or extended, and the voice is not changed |
| `take <beat>.<line> <take>` | Uses a different take's last complete read |
| `lead <beat> <s>` | The beat's first line starts `s` seconds before its picture, overlapping the previous beat (a J-cut) |
| `lock` | Writes `build/timeline.json` (§6.5). Fails if a you-line has no read or a VO line has no audio |
| `unlock` | Deletes `build/timeline.json`. Files fitted to the old timeline are kept but marked out of date |

### 7.9 `pixelreel scene import <export-dir> --id <id>`

Copies a pixellab export into `scenes/<id>/` and writes a starter
`scene.yaml` from it. Behaviour is provisional (§13).

### 7.10 `pixelreel scene fit <id> --mode loop|hold|stretch`

Sets how the scene fills each beat that uses it. The default is `loop`.

| Mode | Behaviour |
|---|---|
| `loop` | Repeats the scene's timeline |
| `hold` | Plays it once, then holds the last frame |
| `stretch` | Time-scales the scene's timeline to the beat's length |

Cues and `#cue` camera keyframes always fire at the cue word's locked
time, whatever the mode.

### 7.11 `pixelreel scene preview <beat>`

Renders that beat alone, with its locked voice, to
`build/preview/<beat>.mp4`. This needs a locked timeline.

### 7.12 `pixelreel asset add <file> --id <id> [--fit trim|hold-last|speed] [--alpha] [--audio keep|mute]`

Probes the file and records it in `assets/assets.yaml` with its hash.
Files outside the project, such as a channel-wide logo, are allowed.

| Fit | Behaviour |
|---|---|
| `trim` (default) | Cuts the asset to the slot; holds the last frame if the asset is shorter |
| `hold-last` | Plays it fully, then holds the last frame |
| `speed` | Retimes it to the slot exactly; audio is retimed without changing pitch |

- `--alpha` requires an alpha-capable format: ProRes 4444, or VP9 WebM
  with alpha.
- Asset audio is mixed in at unity gain unless `--audio mute` is given.

### 7.13 `pixelreel score plan`

Writes `build/score/plan.json` in `cozy-score`'s plan format, using
`[startSeconds, endSeconds]` spans. It uses locked times when the timeline
is locked, and estimates otherwise. Neighbouring beats of the same type
are merged into one section. The plan is validated with
`cozy_score::plan::parse_plan` before it is written.

### 7.14 `pixelreel score render [--seeds a,b,c] [--instruments …] [--stems]`

Builds the plan (§7.13) and calls `cozy_score::render::render` once per
seed, one seed after another to limit memory use.
- Output goes to `build/score/seed-<n>/`: `full.wav`, `no-melody.wav`,
  `cue.json`, and `stems/` if `--stems` is given.
- The default seeds are `picks.yaml`'s seed, or `7`.
- The feel comes from `pixelreel.yaml`.
- Every `cozy-score` note is passed through as a warning.
- For each `title-sting` and `reveal` boundary that `cozy-score` snapped
  by more than 0.1 s, it warns and suggests the `cut set … --length`
  change that would line the hit up with the cut (with `cut unlock` and
  `cut lock` around it when the timeline is locked).

### 7.15 `pixelreel score pick <seed>`

Records the seed in `picks.yaml`. It fails if that seed has not been
rendered.

### 7.16 `pixelreel render --preview | --final [--size WxH] [--codec h264|prores]`

Builds the video as described in §9. Both modes need a locked timeline and
a picked score, and they print exactly which inputs are missing.

| | `--preview` | `--final` |
|---|---|---|
| Size | 960×540 | `--size`, default from `pixelreel.yaml` |
| Overlays | Beat id and type plus timecode, burned in | None |
| `card` pictures | Allowed | Rejected |
| Video | H.264, fast preset | H.264 High, CRF 16, `yuv420p`, or ProRes 422 HQ with `--codec prores` |
| Audio | AAC 192 kbps | AAC-LC 384 kbps, 48 kHz stereo |

Output goes to `build/render/<mode>/`:
- `video.mp4` (or `.mov` for ProRes).
- `captions.srt`: one cue per line, using the storyboard text with cue
  markers stripped and the locked word timings. Lines longer than two rows
  of 42 characters are split at word boundaries.
- `chapters.txt`: `m:ss <title>` for each chapter beat.
- `render-report.json`: per-beat sources and hashes, final loudness and
  true peak, and warnings.

### 7.17 `pixelreel status [--json]`

A grid with one row per beat and one column per stage: script, voice,
cut, picture, music. Each cell shows `✓` (done), `–` (not needed or not
started) or `stale` (inputs changed since it was built). The footer says
whether the timeline is locked and whether the locked timeline is out of
date.

### 7.18 `pixelreel check --youtube [--strict]`

Checks the latest final render. A failure exits with `1`; with
`--strict`, warnings do too.

| Check | Rule | Level |
|---|---|---|
| Chapters | First chapter at 0:00, at least 3 chapters, each at least 10 s | fail |
| End screen | The last beat is `outro-end-screen` and lasts 5–20 s; the video is at least 25 s long | fail |
| Loudness | Integrated −14 ± 1 LUFS; true peak ≤ −1 dBTP | fail |
| Captions | Every line has a caption | fail |
| Media | No missing or out-of-date inputs | fail |
| Placeholders | No `card` pictures | fail |
| Music hits | Snap offset ≤ 0.1 s at `title-sting` and `reveal` | warn |
| Hook | The video opens with `cold-open-hook` beats that last 30 s or less in total | warn |

## 8. Timing model

### 8.1 Beat length

- **Beats with lines:** the span from the first line's start to the last
  line's end, with the joins from §8.2. Then `length:` is applied as a
  minimum, then `cuts.yaml` beat `length` offsets.
- **Beats without lines:** `length:`, or the asset's duration.
- **Beats are back to back.** A beat's `lead` moves its first line's audio
  earlier, overlapping the previous beat's picture. It does not change
  where the picture boundary falls.

### 8.2 Joins between lines

- **You-line in point:** first word start − `pre_roll`.
- **You-line out point:** last word end + `keep_breath`.
- Both then get the `cuts.yaml` offsets added.
- **Two consecutive lines read back to back in the same take:** the
  natural pause is kept, up to `max_gap`.
- **Any other join:** a hard cut. On a `face` picture this is a jump cut.
- **VO lines:** play their whole audio file, trimmed to the first and
  last word with the same padding.

### 8.3 Frame grid

All locked times are rounded to `1/fps`. Audio edits get 10 ms
equal-power crossfades to avoid clicks.

## 9. Composition and mix

### 9.1 Video

Each beat is rendered to a lossless FFV1 intermediate,
`build/render/beats/<beat>-<hash>.mkv`, at the output size. The
intermediates are concatenated and encoded once.

| Picture | How it is rendered |
|---|---|
| `face` | `ffmpeg` cuts the take segments, scales them to cover the frame and centre-crops |
| `scene:` | The crate's compositor draws each frame at canvas resolution, applying layers, sprite animations, cues and the camera. Camera positions are rounded to whole canvas pixels. It upscales by `size ÷ canvas` with nearest-neighbour, which must be a whole number (otherwise an error), and pipes raw RGBA frames into `ffmpeg` |
| `asset:` | `ffmpeg` fits it as in §7.12. With alpha, it is overlaid on the `under:` picture |
| `card` | Text rendered on a flat background |

### 9.2 Audio

1. **Voice bus:** you-line segments from takes plus picked VO takes,
   placed at their locked times.
2. **Asset bus:** asset audio, unless muted.
3. **Music bus:** the picked seed's `full.wav`, resampled to 48 kHz and
   ducked by the voice bus: `duck_db`, `duck_attack_ms`,
   `duck_release_ms`. `cozy-score` deliberately does not duck, so
   `pixelreel` does.
4. **Master:** sum the buses, then normalise to `target_lufs`, measured
   with `cozy-score`'s BS.1770-4 meter. Apply a `true_peak_dbtp` ceiling,
   with true peak measured at 4× oversampling. If the ceiling sets the
   gain, the report says so.

## 10. Caching and staleness

- Every derived file records a sha256 over its inputs: the `pixelreel`
  version, the relevant settings, and the hashes of its input files.
- A file is out of date when that hash no longer matches. Commands rebuild
  only out-of-date files.
- `status` shows the same information as a grid.
- Media files are hashed by content. Hashes are cached by path, size and
  modification time, so large takes are not re-read on every run.
- The same inputs give byte-identical `timeline.json`, `plan.json` and
  score WAVs. Video files depend on `ffmpeg` and are not expected to be
  byte-identical.

## 11. Delivery milestones

| Milestone | Commands | Delivers |
|---|---|---|
| **M1** | `init`, `board`, `score plan`, `score render`, `score pick` | Music sketches from a storyboard alone, using estimated times |
| **M2** | `vo gen`, `vo pick`, `take add`, `cut …`, `status` | A locked timeline from recordings and ElevenLabs lines; `score` uses locked times |
| **M3** | `asset add`, `scene import`, `scene fit`, `scene preview`, `animatic` | Every picture source and the compositor. `scene import` waits on §13 |
| **M4** | `render`, `check --youtube` | The final video, captions, chapters and YouTube checks |

## 12. Testing

- **Unit tests:**
  - storyboard parsing and validation, including every error reported in
    one pass;
  - time and length parsing;
  - estimates;
  - merging beats into the score plan;
  - read detection and alignment, on fixture transcripts;
  - applying `cuts.yaml`;
  - frame rounding;
  - caption splitting;
  - chapter formatting;
  - each YouTube check;
  - the compositor (golden PNG frames for a fixture scene).
- **Integration tests** run on a fixture project whose media is generated
  during the test with `ffmpeg` (`testsrc2`, `sine`):
  - lock, then render a preview;
  - assert the duration, frame count, chapter list and caption count;
  - assert the loudness is within 0.5 LU of target.
- **Determinism:**
  - the sample storyboard (Appendix A) has a golden `plan.json`;
  - `timeline.json` from fixture inputs has a golden hash.
- **No network or model in tests:**
  - ElevenLabs is faked through `PIXELREEL_ELEVENLABS_URL`.
  - Alignment tests use stored transcript JSON.
  - The `whisper-cli` adapter test is skipped when the binary is absent.

## 13. Open question

**What does a pixellab export look like?** Sprite sheets, PNG sequences,
or a layout or metadata file? `scene import` and the final shape of
`scene.yaml` depend on it. The owner will provide an example export
before M3. Until then, §6.6 is provisional. This question does not block
M1, M2 or the rest of M3.

## 14. Risks

| Risk | Mitigation |
|---|---|
| Alignment misses mumbled or ad-libbed lines | `take add` reports lines with no read and unmatched stretches; `cut set` and `cut take` are the manual fixes |
| `cozy-score` memory grows with length (about 2.2 GB peak for 10 min) | Seeds render one after another, never in parallel |
| Snapping to the music grid makes hits miss short voiceless beats | `score render` and `check` report offsets and suggest the exact `cut set … --length` fix. A re-render may pick a new tempo, so the check runs again |
| Re-locking after picking a score leaves the music out of date | `status` and `render` flag the score; `render --final` refuses an out-of-date score |
| Regenerating a VO line shifts later beats | VO is cached by hash and only regenerated with `--force`; `vo gen` warns on locked lines |
| Measured loudness and timing don't make a good video | Out of scope: a person watches `render --preview` before publishing |

## Appendix A: Sample production

The example is a 7:40 devlog, "I Built a Farm That Runs Itself (30-Day
Devlog)", in the usual YouTube shape:
- a hook under 15 s, then a logo sting and a roadmap;
- three chapters that alternate talking head and pixel demos;
- a sponsor read about a third of the way in;
- a quote card to break the pattern;
- a build into a reveal, then a reflective beat;
- a recap with a call to action, and a 20 s end screen.

Sprout, an in-world robot character, is voiced with ElevenLabs.

### A.2 Session

```bash
# 1. Pre-production: script, storyboard, rough timing
pixelreel init farm-devlog --size 1920x1080 --fps 30 --pixel-scale 6 --feel spring
cd farm-devlog
pixelreel board
pixelreel animatic --tts
pixelreel score render --seeds 7

# 2. ElevenLabs lines
pixelreel vo gen --voice sprout --takes 3
pixelreel vo pick quote 2
pixelreel vo pick ch1-demo 1

# 3. Record, then align and cut
pixelreel take add takes/A001.mp4 takes/A002.mp4 takes/A003.mp4
pixelreel cut tighten --max-gap 0.30 --keep-breath 0.12
pixelreel cut show hook
pixelreel cut set hook.2 --out -0.20
pixelreel cut take intro.1 A003
pixelreel cut lead hook-tease 0.4
pixelreel cut lock

# 4. High-fidelity pictures
pixelreel scene import ~/pixellab/exports/farm-night --id farm-night
pixelreel scene import ~/pixellab/exports/sprinkler --id sprinkler
pixelreel scene fit farm-night --mode loop
pixelreel scene fit sprinkler --mode hold
pixelreel scene preview ch2-demo
pixelreel asset add ~/channel/logo-intro.mov --id logo-intro --fit trim
pixelreel asset add assets/quote-card.mov --id quote-card --alpha --fit hold-last
pixelreel asset add ~/channel/end-screen.mov --id end-screen --fit hold-last

# 5. Music from the locked edit
pixelreel score render --seeds 3,7,11
pixelreel score pick 7

# 6. Render
pixelreel render --preview
pixelreel check --youtube
pixelreel render --final --size 3840x2160   # 320x180 art at x12; 4K uploads get a higher YouTube bitrate
```
